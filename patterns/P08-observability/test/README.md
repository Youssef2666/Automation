# P08 test fixtures

- `input.json` - the item a caller passes to the Execute Workflow node (a Set node builds it, see the README).
- `expected.json` - the item that comes back (first call inserts, a second call with the same `execution_id`
  updates), the `execution_log` row, and the two failure shapes (Postgres down, missing status).
- `harness.json` - a manual workflow (`ALP08Harness0000`) generated by the P08 authoring script. It calls P08 twice
  from one run: a `success` row keyed on `$execution.id` and a `warning` row keyed on `$execution.id-warn`, so one
  run leaves two rows (a real caller logs once per run).

Sub-workflows cannot be started from the CLI with input, so the live check goes through the harness:

```bash
bash scripts/import-workflows.sh patterns/P08-observability --publish
docker compose exec -T n8n n8n import:workflow --input=/repo/patterns/P08-observability/test/harness.json
python scripts/dev/run-workflow.py ALP08Harness0000
docker compose exec -T postgres psql -U n8n -d demo -c "select execution_id, workflow_name, status, duration_ms, error_message as notes from execution_log order by id desc limit 2"
python scripts/dev/executions.py --workflow ALP08Observabili --last 2       # mode=integrated, success
```
