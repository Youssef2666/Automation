A self-contained n8n 2.x stack (Docker Compose) plus a **coverage matrix** of 36 workflows and 8 production
patterns. Everything runs offline on your machine against synthetic data: no cloud account, no API key, no card.
Each workflow is a folder with a README, a screenshot, an import-ready `workflow.json` and a test payload. The
`patterns/` section covers what tutorials skip: error handling, retries, idempotency, rate limits, secrets,
observability.

## Quick start

Needs Docker Desktop or Docker Engine with Compose v2, Python 3.10+, and Bash (Git Bash on Windows).
Core profile baseline: 2 vCPU, 4 GB RAM, 5 GB disk.

```bash
git clone https://github.com/Youssef2666/Automation.git && cd Automation
cp .env.example .env                               # dummy values; edit before exposing anything
docker compose --profile core up -d                # n8n, Postgres, Redis, Mailpit, GreenMail, MinIO, mock-api
bash scripts/setup.sh                              # owner account, API key, credentials, import, publish
```

Then open <http://localhost:5678> and log in as `owner@lab.local` with the `N8N_OWNER_PASSWORD` from your `.env`.
Every workflow is already imported; the ones marked `autopublish: true` are live.

Fire the first workflow (T01, webhook to Postgres) and watch the row land:

```bash
curl -X POST http://localhost:5678/webhook/t01-orders \
  -H 'Content-Type: application/json' \
  -d @workflows/T01-webhook-to-database/test/payload.json

docker compose exec -T postgres psql -U n8n -d demo -c 'select id, source, event_type from webhook_events'
```

`python scripts/dev/smoke.py` does the same end to end and prints the clone-to-first-execution time (target: under
10 minutes, PRD goal G2). The exact webhook path and headers for each workflow are in that workflow's README.

## What's inside

```
docker-compose.yml     compose stack at the repo root (profiles: core, docs, ai, observability, queue)
docker/                image sources: mock-api (json-server), docgen (FastAPI), postgres init script
seed/                  schema.sql, seed.sql, sample files and payloads - all synthetic, generated by generate_seed.py
workflows/<ID>-slug/   README.md, workflow.json, assets/screenshot.png, test/      (one folder per workflow)
patterns/<PNN>-slug/   same contract; reusable sub-workflows and the write-up of the pattern
scripts/               setup, bootstrap, import/export, validate, build-matrix, render-preview, dev helpers
docs/                  PRD, tool comparison, security, observability, ADRs
.github/workflows/     validate, matrix, links, compose-smoke, release, triage
```

Catalog ids: `T` triggers, `D` data and ETL, `M` monitoring, `R` documents and reports, `A` AI, `B` business ops,
`O` DevOps, `P` patterns. A folder is `shipped` only after it imports cleanly, executes against seeded data, has a
current screenshot and passes `scripts/validate.py` (see [CONTRIBUTING.md](CONTRIBUTING.md)).

## Profiles

| Profile | Adds | Host ports | Baseline |
|---|---|---|---|
| `core` | n8n, Postgres, Redis, Mailpit, GreenMail, MinIO, mock-api | 5678, 5432, 6379, 8025/1025, 3025/3143, 9000/9001, 8080 | 2 vCPU, 4 GB RAM, 5 GB disk |
| `docs` | docgen (PDF, DOCX/PPTX with Arabic RTL, PDF table extraction, OCR) | 8090 | +1 GB RAM |
| `ai` | Ollama, Qdrant, Whisper | 11434, 6333, 9010 | 4 vCPU, 8 GB RAM, 15 GB disk (model download ~2.3 GB) |
| `observability` | Metabase | 3001 | +1 GB RAM |
| `queue` | n8n worker (`EXECUTIONS_MODE=queue`) | none | optional, for the scaling demo only |

```bash
docker compose --profile core --profile docs up -d
docker compose --profile core --profile ai up -d            # first start pulls the models
docker compose --profile core --profile observability up -d
docker compose ps && docker compose logs -f n8n
```

Do not start the `ai` profile on a machine with less than 8 GB RAM; every AI workflow README names a smaller model
fallback via `OLLAMA_MODEL`.

| mock-api | built from `docker/mock-api` (json-server 0.17) | <http://localhost:8080> | pagination, flaky and rate-limited endpoints, RSS, HTML catalog, FX rates |
| docgen | built from `docker/docgen` (FastAPI) | <http://localhost:8090/health> | PDF, DOCX, PPTX, table extraction, OCR |

Credentials are created once by `scripts/setup.sh` from `.env` and referenced in every workflow by a fixed id and
name (`Postgres - demo`, `SMTP - Mailpit`, `S3 - MinIO`, ...). Workflows never read environment variables directly
(`N8N_BLOCK_ENV_ACCESS_IN_NODE=true`).

## Optional external variants

The core path of every item runs with the stack above. Two items have an optional external variant; leave the
variables empty and the bootstrap skips those credentials.

| Variable in `.env` | Enables | Without it |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | T07 Telegram command router with a real bot (free bot from BotFather) | T07 README documents the local alternative (webhook-driven command router) |
| `GITHUB_TOKEN` | M02 / O04 talk to the GitHub API | M02 uses the mock-api `/events` feed; O04 exports to the mounted `data/export/` folder |

Nothing in the repo requires a paid tier, and no workflow is marked `shipped` on the strength of an external variant.

## Development

```bash
python scripts/validate.py [folder] [--strict] [--docs]     # folder contract, JSON structure, secret scan, links
python scripts/build-matrix.py [--check]                    # regenerate (or verify) the matrix above
python scripts/render-preview.py <folder>                   # draw assets/screenshot.png from workflow.json
bash scripts/import-workflows.sh <folder> [--publish]       # push one folder into the running n8n
bash scripts/export-workflows.sh [ID ...]                   # pull from n8n, strip credentials, pretty-print
bash scripts/reseed.sh                                      # drop and reload only the demo database
python scripts/scaffold.py <ID> <slug> "<Title>"            # new workflow/pattern folder from the template
```

A `Makefile` wraps the same commands; `make help` lists the targets. Workflow JSON is never hand-written: each
workflow has an authoring script under `.claude/skills/n8n-workflow-json/authoring/` that generates `workflow.json`
with deterministic ids ([ADR 0004](docs/decisions/0004-generated-workflow-json.md)).

With [Claude Code](https://claude.com/claude-code) the repo ships slash commands (`/new-workflow`, `/validate`,
`/build-matrix`, `/stack`, `/import`, `/export`, `/ship-check`, `/smoke`, `/adr`, ...) and agents
(`workflow-builder`, `workflow-reviewer`, `qa-runner`, `docs-writer`) under `.claude/`. Hooks block secrets on
write and destructive shell commands. None of this is required to use the repo.

## Security

This is a local lab, not a hardened deployment. No secrets are committed (`.env` is git-ignored; `.env.example`
holds dummy values), credentials are imported at bootstrap from `.env`, Execute Command is disabled, file access is
restricted to `/home/node/.n8n-files`, and webhooks use a header key. A secret scan runs in the Claude Code hooks and
blocks CI. Before exposing anything beyond `localhost`, read [docs/security.md](docs/security.md). Report issues per
[SECURITY.md](SECURITY.md).
