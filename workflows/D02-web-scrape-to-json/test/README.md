# D02 test fixtures

- `catalog-page-1.html` - page 1 of the mock catalog as returned by `curl 'localhost:8080/catalog?page=1'`
  (14 `article.product` cards, `<main id="catalog" data-page="1" data-pages="3">`, `<a rel="next">`). This is the
  shape the two HTML nodes' selectors expect; compare it with `data/out/catalog-scrape.json` after a run.
- `fixture-variant.json` - the same workflow with the gate + HTTP fetch replaced by an inline two-page fixture
  (`Fixture page (no network)`), generated by `build("fixture")` in the authoring script. Its five cards cover
  every validation rule: one clean card, one without a `.price` (price + currency invalid), one with
  `data-sku="SKU-BAD"` and `ships soon` as stock (sku invalid, stock unreadable), a duplicate of the page-1 SKU
  on page 2, and one clean `out of stock` card. Page 2 has no `rel=next`, which ends the loop.

Replay the fixture without touching the network:

```bash
export MSYS_NO_PATHCONV=1   # Git Bash only: keep /tmp as a container path
docker compose cp workflows/D02-web-scrape-to-json/test/fixture-variant.json n8n:/tmp/d02-fixture.json
docker compose exec -T n8n n8n import:workflow --input=/tmp/d02-fixture.json
python scripts/dev/run-workflow.py ALD02FixtureVari
python scripts/dev/executions.py --workflow ALD02FixtureVari --last 1
cat data/out/catalog-scrape-fixture.json           # 2 rows: SKU-9001 (page 1), SKU-9003 (page 2, stock 0)
cat data/out/catalog-scrape-fixture-rejects.json   # 3 rows with _errors
```

Expected `_errors`:

| page | card | sku | _errors |
|---|---|---|---|
| 1 | 2 | SKU-9002 | `price invalid: ""; currency invalid: ""` |
| 1 | 3 | SKU-BAD | `sku invalid: "SKU-BAD"; stock unreadable: "ships soon"` |
| 2 | 1 | SKU-9001 | `duplicate sku (already scraped on an earlier card or page)` |

The fixture run also uploads `artifacts/scrapes/catalog-scrape-fixture-<yyyyLLdd>.json` and inserts a
`documents` row (`kind = scrape`, `meta.rejected = 3`), so the storage path is exercised end-to-end as well.

To simulate a dead site for the main workflow: `docker compose stop mock-api`, run `python scripts/dev/run-workflow.py D02`
(the HTTP node retries three times, then the execution fails and P01 logs it), then `docker compose start mock-api`.
